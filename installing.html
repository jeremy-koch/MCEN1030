Getting going in your language

Colab first, your own machine when you’re ready

A few recommendations, if you want them. The honest headline: you can do this entire course in Google Colab — nothing to install, works on any machine including a locked-down Chromebook, and it’s where the lessons and activities assume you are. Start there; most of you can stay there.

But at some point — the design project is a natural moment — running Python on your own machine starts paying off: your files live where you can see them, nothing depends on a wifi connection, and you get a real editor. This page is for that moment. MATLAB has some special steps because we have a license through the school, though overall its installation is probably the easiest of everything here.

Important

I considered giving NO instructions for installing Python, because local setups require some care and occasional maintenance during the semester — and I want you willing and able to handle that yourselves. (Chasing down an installation problem is excellent training for this course’s whole philosophy.) But I relented. Recommendations below — and you will need to do a bit of work from the command line. If you flat-out do not want to do command-line stuff, stay in Colab or go with MATLAB. But for what it’s worth: it makes me feel powerful to do command-line stuff.

Level 0: Google Colab (where everyone starts)

Go to colab.research.google.com, sign in with your university Google account, click New notebook. That’s the entire installation. Python runs on Google’s computers; NumPy, matplotlib, and pandas are pre-installed; your notebooks live in your Google Drive. The one thing to learn early is file handling — where an uploaded CSV goes and why it vanishes when the session ends — which is what Base Camp’s BC1 session covers.

Level 1: Python on your machine

There are multiple avenues here, and if you are confident enough to find your own way (e.g., with pip and venv), I believe in you.

My recommendation is to install miniconda — NOT the full Anaconda, which you can find nearby if you really want to, but I’m not linking it. Anaconda is attractive: everything you’d ever need in one install. Also a lot you’ll never need, plus a sluggish navigator that insists on cross-checking every package each time you update. I grew to hate it and “downgraded” to miniconda: no navigator, way fewer packages, no regrets.

For the editor, I recommend VS Code — it supports Jupyter notebooks (so your Colab habits transfer directly), has an integrated terminal, and its GitHub integration will matter to anyone who takes the version-control Side Quest. Install VS Code, then its Python and Jupyter extensions (VS Code will offer them the first time you open a .py or .ipynb file).

Package management

Miniconda starts with essentially no packages, so you’ll install what you need from the command line. NumPy, matplotlib, and pandas cover this course; this page has the instructions. Note that miniconda still uses conda as the command.

pip is another package-management option — really not that different from conda. If you have reason to go that way, do it; plenty of tutorials around.

TipAlso worth installing

Seaborn sits on top of matplotlib and is beautiful. SciPy is a deep toolbox of numerical routines — and unlike some later courses that make you build tools from fundamentals, nothing in this course forbids it: our concern is whether you can specify and verify, not whether you hand-rolled the algorithm. For the ML-taster Side Quest, scikit-learn is what we’ll reach for.

NotePython “environments” (optional reading)

Serious programmers give each project its own isolated “environment” with its own package versions, because packages sometimes conflict (the classic: some ML libraries lag behind the newest NumPy). For this course, working entirely in the base environment is fine. If you want the habit early: conda create --name mcen1030, then conda activate mcen1030, then conda install numpy installs into just that environment. Note you install per-environment — three environments can mean NumPy installed three times, and that’s normal.

Level 2: MATLAB (week 11 and beyond)

MATLAB is the easiest install of everything on this page. As a CU student you have free access: create a MathWorks account with your CU email — instructions are here, under the student “How to get it.”

Once your account is tied to the school’s license, you can install desktop MATLAB or use MATLAB Online in the browser — students have used both, and you can hop back and forth. I like the immediacy of a local install and it runs a bit faster; Online gives you your code from any computer. For this course’s purposes (week 11’s translation work and HW 9), MATLAB Online is entirely sufficient — treat it as MATLAB’s Colab.

Basic MATLAB is all this course needs; no toolboxes required. If you’re going on in the department, toolboxes like Simulink (used in System Dynamics) can be added anytime, so there’s no need to decide now.

The MathWorks “MATLAB Onramp” tutorial — find it under Online Training at matlab.mathworks.com — is genuinely good, takes about two hours, and is the recommended pre-read for week 11 if you want a head start.

Which level do I need, and when?

Weeks 1–10: Level 0 is enough, full stop — and the lesson pages themselves run Python in your browser for quick experiments, which is Level −1. The project (weeks 11–14): Level 0 still works, but Level 1 makes multi-file work and file management dramatically saner, and teams that take the Git Side Quest will want it. Week 11 / HW 9: Level 2, and MATLAB Online is fine. If your machine fights you at any point: bring it to a Monday session — installation archaeology is a group sport.
