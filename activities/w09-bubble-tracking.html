Tracking bubbles

Week 9 Thursday · 2 engagement credits

On Tuesday we treated an image as a grid of numbers. Each frame of a video is an image, and so videos are just a series of such grids. Today we’ll use that to do something no human could do by hand: follow thousands of bubbles rising through a glass.

The video is a pint of a carbonated beverage, filmed on my phone in slow motion. Watch it first (it’s 26 seconds), and before writing any code, talk with your group:

  • Do the bubbles all rise at the same speed?
  • Does a bubble speed up as it rises? Slow down? Stay the same?
  • How long does a bubble take to get from the bottom of a real glass to the top? (Picture the last fizzy drink you watched. Is it closer to 0.3 seconds, 3 seconds, or 30?)

The tool we’ll use is trackpy, a Python package written by physicists who track particles. We’re more-or-less borrowing their walkthrough but with our own video, and I’ve streamlined it a bit.

Setup

In Colab, the first cell installs trackpy (Colab already has everything else):

!pip install trackpy

In VS Code, run pip install trackpy opencv-python once in the terminal instead. And if you’re reading the trackpy walkthrough alongside this, you’ll see it uses a package called pims to read video. We skip pims entirely and use cv2 (that’s OpenCV) to read the video, because it comes preinstalled on Colab.

Then the imports, and a download of the video into your notebook:

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
import cv2
import trackpy as tp
from urllib.request import urlretrieve

urlretrieve("https://jeremy-koch.github.io/MCEN1030/data/bubbles.mp4", "bubbles.mp4")

Read the video

Here’s a function that opens a video file and hands back count frames, starting at frame start, each one converted to grayscale. (We don’t need color to find bubbles, and grayscale is one grid per frame instead of three.)

def read_frames(path, start, count):
    """Read `count` grayscale frames from a video, starting at frame `start`.
    Returns a 3D array: (frame, row, column)."""
    video = cv2.VideoCapture(path)
    video.set(cv2.CAP_PROP_POS_FRAMES, start)
    frames = []
    for k in range(count):
        ok, frame = video.read()
        if not ok:
            break
        frames.append(cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY))
    return np.array(frames)

frames = read_frames("bubbles.mp4", 0, 150)
print(frames.shape)

plt.imshow(frames[0], cmap="gray")
plt.show()

(We’ll look at 150 of the video’s 779 frames, that’s plenty.)

TipYou’re on track if…

frames.shape is (150, 1280, 720): 150 frames, each 1280 rows tall and 720 columns wide.

Find the bubbles (first try)

trackpy’s locate looks at one frame and finds every blob that’s brighter than its surroundings. The one number it requires as an input is diameter: roughly how many pixels across a feature is. It has to be odd, and our bubbles are tiny, so let’s try 5:

f = tp.locate(frames[0], 5)
print(len(f), "features found")

tp.annotate(f, frames[0])

Every red circle is something trackpy thinks is a bubble… you should find somewhere around 5,000 “bubbles,” and circles all over the table, the glare, the logo on the glass. Not all of the bright blobs are bubbles, so we need to pare this down somehow.

The trick: keep only what moves

An observation: the table doesn’t move, the glare doesn’t move, the glass doesn’t move. So let’s take the median of all 150 frames, pixel by pixel. A pixel on the table is the same in every frame, so its median is just… the table. Subtract that from each frame, and whatever is left over is what moved.

First, let’s crop to just the glass (rows 100–950, columns 100–680) so we’re not doing math on the table:

glass = frames[:, 100:950, 100:680]

background = np.median(glass, axis=0).astype(np.float32)
moving = np.clip(glass - background, 0, None)

fig, ax = plt.subplots(1, 3, figsize=(12, 6))
ax[0].imshow(glass[0], cmap="gray")
ax[0].set_title("frame 0")
ax[1].imshow(background, cmap="gray")
ax[1].set_title("background (median)")
ax[2].imshow(moving[0], cmap="gray")
ax[2].set_title("frame 0 minus background")
plt.show()

axis=0 means “take the median across frames,” so background is a single picture. The np.clip(..., 0, None) sets anything negative to zero: we only want things brighter than the background.

TipYou’re on track if…

The middle picture looks like the glass with almost no bubbles in it. The right-hand one is mostly black, with lots of small bright specks in the liquid and almost nothing on the table.

This is called background subtraction. Traffic cameras, security cameras, and wildlife cameras all use some version of it.

Find the bubbles (second try)

Same locate, on the background-subtracted frame:

f = tp.locate(moving[0], 5)
print(len(f), "features found")

plt.hist(f["mass"], bins=50)
plt.xlabel("mass (total brightness)")
plt.ylabel("number of features")
plt.show()

trackpy reports a mass for each feature: its total brightness. Real bubbles are bright; faint specks are often just noise in the video. The trackpy walkthrough’s advice is to look at this histogram and pick a minmass that cuts off the dim junk.

TipYou’re on track if…

You find roughly 3,000 features, with masses from about 10 up to 150 or so, piled up on the low end with a long tail to the right. There’s no clean gap here (unlike the walkthrough’s beads), so the cutoff is a judgment call. We’ll use minmass=40, which keeps about 1,700. Anything from 30 to 60 works fine.

f = tp.locate(moving[0], 5, minmass=40)
print(len(f), "features found")

tp.annotate(f, moving[0])

Now the circles should be in the liquid. Look closely at a few of them on the original frame (glass[0]). Are they bubbles?

Find the bubbles in every frame

tp.batch runs locate on each frame and stacks all the results into one big pandas DataFrame, with a frame column so we know which feature came from where:

f = tp.batch(moving, 5, minmass=40, processes=1)
print(len(f), "features in", len(moving), "frames")
f.head()

(processes=1 tells it to do one frame at a time.)

TipYou’re on track if…

It takes somewhere between 20 seconds and a minute, and finds roughly 1,500–2,000 features per frame. Note: 150 frames$$2000 features per frame = 300,000 things identified in a minute!

Link them into trajectories

So… we have a quarter million dots, but dot 142,567 is actually dot 139,212 one frame later — we need to link them. TrackPy looks in adjacent frames for the nearest feature within search_range pixels of a dot and says “that’s probably the same one.”

How far does a bubble move between frames? Showing moving[0] and moving[1] reveals it’s a pixel or two. So a search_range of 5 gives some breathing room. memory=2 lets a bubble disappear for up to two frames (behind a reflection, say) and still be recognized when it comes back.

t = tp.link(f, search_range=5, memory=2)
t = tp.filter_stubs(t, 10)
print(t["particle"].nunique(), "trajectories")

filter_stubs throws away any trajectory shorter than 10 frames. Those are mostly flickers, not bubbles.

Then let’s make a really cool plot:

plt.figure(figsize=(6, 9))
tp.plot_traj(t, superimpose=glass[0])
plt.show()
TipYou’re on track if…

You have several thousand trajectories, and the plot is a forest of short, mostly vertical colored streaks, dense in the upper two-thirds of the glass and sparser near the bottom.

Every streak is a bubble that a computer found, followed, and labeled.

How fast is each bubble going?

For each trajectory, we can ask: how far did it rise, and how many frames did that take? Rise divided by frames gives a speed in pixels per frame. pandas’ groupby does this for every bubble at once:

tracks = t.groupby("particle").agg(
    y_start=("y", "first"),
    y_end=("y", "last"),
    f_start=("frame", "first"),
    f_end=("frame", "last"),
    y_mid=("y", "mean"),
)
tracks["rise"] = (tracks["y_start"] - tracks["y_end"]) / (tracks["f_end"] - tracks["f_start"])
tracks.head()

Now we have one row per bubble. A quick check on the signs: in an image, row numbers grow downward, so a rising bubble’s y gets smaller, hence the y_start - y_end.

Let’s look at all of these speeds at once:

plt.hist(tracks["rise"], bins=60)
plt.xlabel("rise speed (pixels per frame)")
plt.ylabel("number of trajectories")
plt.show()
TipYou’re on track if…

You see two things: a tall, narrow spike right at zero, and a broad hump centered around 1 pixel per frame that trails off by about 3.

That spike at zero is from “bubbles” that don’t rise. What could they be? (Look back at your trajectory plot: where are the tiny, stubby tracks?) We’ll keep only trajectories that rise at least 0.3 pixels per frame, using some pandas filtering:

rising = tracks[tracks["rise"] > 0.3].copy()
print(len(rising), "rising bubbles out of", len(tracks))

That should drop about 20% of them.

From pixels per frame to cm/s

Pixels to centimeters. We need something of known size in the picture, and the best candidate is the glass itself. In the full, uncropped frame, the rim at the top of the glass runs from about x = 100 to about x = 680, so it’s about 580 pixels across. A pint glass rim is about 9 cm across. So:

px_per_cm = 580 / 9
print(px_per_cm)

That is, our estimate is about 64 pixels per cm. (I didn’t measure the glass two years ago when I shot the video, so maybe it is actually 8.5 cm or 9.2 cm, but let’s not worry about it.)

Frames to seconds. The video plays at 30 frames per second, but it was filmed in 1/8× slow motion. So one second of video is only 1/8 of a second of real life. That is, there are 30 × 8 = 240 frames per real second.

rising["speed"] = rising["rise"] * 30 * 8 / px_per_cm      # cm/s
print(rising["speed"].describe())
TipYou’re on track if…

The median speed is about 4–5 cm/s.

A sanity check on the physics: the liquid is about 13 cm deep. At a few cm/s, how long does a bubble take to get from the bottom to the top? Compare that to your guess from the beginning.

Does a bubble speed up?

Now the question we came for. We need each bubble’s height above the bottom of the glass. In our cropped picture, the glass floor is at about y = 840, and remember that y grows downward:

rising["height"] = (840 - rising["y_mid"]) / px_per_cm      # cm above the glass floor

plt.scatter(rising["height"], rising["speed"], s=2, alpha=0.3)
plt.xlabel("height above glass floor (cm)")
plt.ylabel("rise speed (cm/s)")
plt.show()

There might be a trend in there, but the scatter is big enough that it’s hard to say. What we want is the typical speed at each height. So let’s chop the glass into 1 cm tall slices and take the median speed in each slice. The code snippet: height // 1 rounds each height down to a whole number of cm, so every bubble between 4 and 5 cm gets the label 4, and so on. Adding 0.5 puts the label in the middle of the slice:

rising["band"] = rising["height"] // 1 + 0.5

summary = rising.groupby("band")["speed"].agg(["median", "count"])
print(summary)

Then put the medians on top of the cloud:

plt.scatter(rising["height"], rising["speed"], s=2, alpha=0.3, label="each bubble")
plt.plot(summary.index, summary["median"], "o-", color="red", label="median in each 1 cm slice")
plt.xlabel("height above glass floor (cm)")
plt.ylabel("rise speed (cm/s)")
plt.legend()
plt.show()
TipYou’re on track if…

Your table has about 13 rows (heights from 0.5 to 12.5 cm). The bottom couple of slices only have tens of bubbles, while the middle ones have hundreds. The medians start around 2 cm/s near the bottom and climb to about 5–6 cm/s somewhere around 9–10 cm up. Then something happens near the top.

Why would a bubble speed up?

Here’s a story you can hold in your head. A bubble in a carbonated drink isn’t a fixed thing: the liquid is full of dissolved CO₂, and as the bubble rises, more CO₂ diffuses into it. So the bubble grows on the way up. And bigger bubbles rise faster.

Remember terminal speed from the drag lab? When drag balances the push, acceleration is zero, and the speed stops changing. A bubble this small gets to its terminal speed in a few milliseconds, so at every height, it’s essentially at the terminal speed for its current size. The difference from the balloon in the drag lab: the balloon sped up toward one fixed terminal speed. The bubble’s terminal speed is a moving target, because the bubble keeps growing.

For very small things moving slowly through a liquid, drag is proportional to the speed (not the speed squared, like it was for things “bigger than a raindrop” in the drag lab). Set drag equal to buoyancy and you get a terminal speed of1

\[ v = \frac{g\,d^2}{18\,\nu} \]

where \(d\) is the bubble’s diameter and \(\nu\) (the Greek letter “nu”) is the liquid’s kinematic viscosity, a measure of how syrupy it is. For water, \(\nu \approx 1.0\times10^{-6}\) m²/s, and carbonated drinks aren’t far off. Notice the \(d^2\): double the diameter, and the bubble rises four times as fast.

So now we can build a model. Start a bubble at the glass floor with some diameter \(d_0\), let its diameter grow at a steady rate, and step it upward through time, just like the falling ball from week 5 (position += velocity * dt):

def grow_bubble(d0, growth):
    """Simulate one bubble rising from the glass floor while it grows.
    d0: starting diameter (m). growth: how fast the diameter grows (m/s).
    Returns lists of heights (cm) and speeds (cm/s)."""
    g = 9.8
    nu = 1.0e-6         # kinematic viscosity, m^2/s (water's value)
    d = d0
    y = 0.0
    dt = 0.001
    heights = []
    speeds = []
    while y < 0.13:     # 13 cm of liquid
        v = g * d**2 / (18 * nu)
        y = y + v * dt
        d = d + growth * dt
        heights.append(100 * y)
        speeds.append(100 * v)
    return heights, speeds

Start with a bubble that doesn’t grow (growth = 0) and put it on your plot:

model_h, model_v = grow_bubble(0.2e-3, 0.0)     # 0.2 mm, no growth

plt.scatter(rising["height"], rising["speed"], s=2, alpha=0.3, label="each bubble")
plt.plot(summary.index, summary["median"], "o-", color="red", label="median in each 1 cm slice")
plt.plot(model_h, model_v, "k-", linewidth=2, label="model")
plt.xlabel("height above glass floor (cm)")
plt.ylabel("rise speed (cm/s)")
plt.legend()
plt.show()

A bubble that doesn’t grow rises at constant speed, so the model is a flat line. That’s clearly not what the data do! Now turn on growth and adjust the two numbers (d0 and growth) until the model follows the red medians as well as you can.

TipYou’re on track if…

Good matches to the bottom 10 cm or so have a starting diameter a bit over 0.1 mm and a growth rate of a few hundredths of a mm per second (something like 0.05e-3). Several combinations look about equally good, which is worth noticing. The model cannot match the top couple of cm.

Footnotes

  1. This is Stokes’ law, which you may meet again in fluids. Strictly, it’s for things moving so slowly that the liquid flows smoothly around them, and our biggest bubbles are pushing that limit. The honest consequence: the formula slightly overpredicts the speed for a given size, so the diameters we get out of it are probably underestimates, maybe by as much as 1.5× for the fastest bubbles. It’s a fine model for today, and a great example of a model that’s “right enough.”↩︎
