For loops, and picking things out by index

Week 4, Lesson B — read before Thursday

With NumPy arrays, we were able to take a bunch of wind speeds, throw them into a function we’d already written (with single wind speeds in mind), and get the corresponding power production back.

There’s another way we could have done this — a for loop. With a for loop, we go through the list of values one-by-one and perform the calculation. If that sounds less efficient, that’s because it is less efficient… so why would we ever want to use for? The answer is that arrays are great at one calculation, many numbers, but they are less capable when we need to consider many options and perform many calculations. In our design process, we wouldn’t have one turbine with a collection of wind speeds, we’d have five candidate turbines with a collection of wind speeds — which one is best? The for loop will help us with this calculation.

Think First

Recall

  1. What does speeds[power.argmax()] get you?
  2. What does speeds[speeds >= 3] get you?

Look Ahead

  1. Suppose you want the total day’s energy for five different rotor diameters. How many lines of code is that?
  2. If a calculation gives you five answers, one per design, where do those five answers go? They aren’t the input array, and they aren’t a single number.

“Wait, couldn’t NumPy do that?”

Here is something with a for loop

and here is something very similar without

The first one, with the for, is longer to write and longer to run — it is less efficient. So… why do we need for loops? I’ll try to say something general:

  • Arrays are good at holding data and then having math done on them. Very easy to cube every element in a list of 100 speeds in one line: speeds**3.
  • Loops are good at going through a collection of cases you are comparing. Five rotor diameters. Twelve tilt angles. Three modeling assumptions. Each pass through the loop produces a whole array’s worth of results (and then you’ve got to figure out what to do from there!).

Loop over designs, array inside

Let’s revisit the turbine calculation:

What happened on each pass through the for loop? The function turbine_power(good, D) handed back an array of seventeen powers. Then .sum() collapsed those seventeen numbers into one day’s energy. Then the loop moved on and did it again for the next diameter, then for the next diameter, and the next. In total we tested five diameters, each time using NumPy arrays+math to do the calculations necessary to get power.

Notice we didn’t change turbine_power. The power of functions, if you are thoughtful about how to build them, is that you can keep the same math inside them and just vary the inputs.

Where do the values go?

We’ve been relying on print a lot in this class, because we (humans) can see the answers. We also know we can save the values under a variable name. But now we are going to be producing massive amounts of data — large arrays for each test case… where do we store those values?

Option 1 — grow a list with append

Probably the most common method: create an empty list and append to it as you go through your for loop:

Three things happened here:

  1. totals = [] makes an empty list before the loop — before, because anything created inside the loop would get wiped clean at the top of every pass.
  2. totals.append(x) tacks x onto the end, so the list grows by one each time through.
  3. np.array(...) converts the finished list into something we can do math on (recall that Python lists don’t cooperate with math).

Option 2 — pre-allocate and fill by index

Before the loop starts, build an array of the right size and fill it with placeholder values. Then each pass through the loop drops its answer into the slot that belongs to it. We know we’re testing multiple diameters, each needs a slot — and np.zeros(len(diameters)) gets that for us.

Same five numbers, by a different route. Three things happened here too:

  1. totals = np.zeros(len(diameters)) builds the answer array before the loop, already the right size. len(diameters) is 5, so we get five zeros. Writing len(diameters) instead of just 5 means that when you change the list of designs, the answer array changes with it — you don’t have to remember to update a number in two places.
  2. range(len(diameters)) is the sequence 0, 1, 2, 3, 4 — every valid index of diameters. So this loop hands us positions rather than values, and we use the position twice.
  3. Every time through the loop, we have set i to a particular value: 0, 1, 2, 3, then 4. Then totals[i] = ... drops one answer into slot i. We read diameters[i] and we write totals[i], both at the same index, on the same pass.

That third point explains why we do this: diameters[2] is the 100 m rotor and totals[2] is what the 100 m rotor made.

CautionZeros are a real number

If your loop skips a slot — you looped over range(4) when there were five designs, say — the last slot stays zero and there is no warning that you forgot about it.

The safer habit is to prefill with something that can’t be mistaken for an answer. np.full(len(diameters), np.nan) fills the array with nan — “not a number”. Any nan you fail to overwrite will poison every sum and max that it is involved in, loudly.

Option 3 — the list comprehension

There’s a third way that is difficult to comprehend but actually quite nice when you get used to it.

The whole loop — the empty container, the five passes, the collecting — has collapsed into that one bracketed expression towards the bottom. The trick to reading it is that the for is still in there, just moved. Read it back-to-front: for each D in diameters, evaluate turbine_power(good, D).sum(), and collect the results in a list. It’s the same as Option 1 but very succinct. The square brackets are doing the job that totals = [] and .append() were doing, which is why they’re brackets.

This is the most Pythonic of the three — that’s a real word people use, meaning roughly “written the way the language wants to be written.”

Option 3 is beautiful once it starts making sense! But it is dense and hard to read. Get comfortable with the other methods first.

Indexing: getting one thing back out

Now that we’ve got a variable that contains all of our values, we can investigate them.

How to interpret the last line of this code:

  • totals.argmax() is 4 — the index of the largest energy.
  • diameters[4] is 120.0 — the design that lives at index 4.
  • So diameters[totals.argmax()] is “the diameter belonging to the best result.”

The two arrays are parallel: index 3 means the 110 m rotor in diameters and it means the 110 m rotor’s energy in totals, because we built them that way. Keeping parallel arrays lined up is important — if you mask one and forget to mask the other, index 3 no longer means the same design in both, a great way to confuse yourself or create incorrect results!

ImportantReminder: counting from zero

There is no totals[5] — you’ll get an IndexError.

Negative indices count from the right: totals[-1] is the last one, totals[-2] the second-to-last. This is useful: totals[-1] looks so much nicer than totals[len(totals)-1].
