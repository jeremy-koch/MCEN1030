Packages and arrays

Week 4, Lesson A — read before Tuesday

Week 3 ended with a question: we wanted to know which wind speed produced the most power, and the only tool you had available was calling the function over and over by hand.

Let’s give a bit more narrative: let’s suppose we are trying to estimate the amount of energy that would be produced by our turbine, based on wind speed data taken every hour. Calling your function 24 times by hand is… fine. But there is a better approach (and there will be problems in our future that necessitate calling a function 1000 times, so we’ll soon require a better approach).

This lesson introduces two ideas that will help us solve this problem: packages (code other people already wrote for you) and arrays (many numbers stored under one variable name). By the end, those 24 function calls become one line… and then we’ll worry about whether to believe it.

Packages: code other people already wrote

Almost nothing you compute as an engineer will be built from scratch. Someone has already written, tested, and optimized code for square roots, statistics, curve fits, plotting, and file reading — and they’ve collected that code into a package you can import and use.

The big one for us is NumPy, short for numerical python, which includes pretty much all of the basic mathematical functions used by engineers. Mathematical operations like \(\sqrt{x}\) and \(\exp{(x)}\) are useful:

I originally planned to hold-off on packages until later, but many of you were importing NumPy to get np.pi on Thursday. This nudged me towards introducing this now!

What did we do here? Step 1 is to import the package. It is typical that the very first line of your code is import numpy as np. This loads the package so that we can use the tools within it, and the as np part gives it a shorter nickname so that we can write np.sqrt instead of numpy.sqrt. (Everyone uses np, so let’s copy that convention.)

When it comes to calling the functions within the NumPy package: yes, the np. prefix is mandatory. It tells the program to call the function from the NumPy package, not from Python itself. “Base” Python does not have a built-in function called sqrt, we have to look within the NumPy package for its np.sqrt function.

There are technically ways to circumvent the np. prefix, but they are discouraged.

TipThink

The np.sqrt function has been verified by millions of users over thirty years and it is far more trustworthy than anything you or an LLM will write this semester. While np.sqrt is rock-solid, you are still responsible for using it in the right place, with the right data, etc. That is, you’ll still need to verify you are using it in the correct way.

Lists: several numbers under one name

The biggest thing NumPy gets us is the ability to do math on many numbers at once. In (base) Python we can create a list of values by putting the numbers inside square brackets, separated by commas

One thing that is true with both Python lists and NumPy arrays (which we are about to introduce): they are labeled/“indexed” starting with zero. “The first” number in the list above can be retrieved using speeds[0], and so we might say speeds[4] is the fifth element.

Thoughtful engineers who use Python a lot will call these the “zeroth” elements and “fourth” elements, or “index zero” and “index four”, but it takes a mental shift to be comfortable looking at a list of numbers and then use those names.

By the way: MATLAB counts from 1. I teach in both languages and get tripped up!

The NumPy array

A subtle shift in language: NumPy works with arrays, and those arrays are going to be able to do the math we hoped Python lists would do:

Technically we build an array using a Python list: np.array(...) is a function that takes as its input a list, here [4.5, 6.2, 7.8, ...]. The function turns that input into a NumPy array, and importantly, arrays will do arithmetic elementwise — the operation happens to every value at once, and you get an array of results back. If our NumPy array has eight elements and we use np.sqrt on it, we are going to get an output with eight elements.

It is hard to overstate the importance of this. When you go to do an engineering analysis, you might have a huge collection of numbers. You can store that whole list as a NumPy array with a single variable name, speeds. Then you can cube every number in that list with speeds**3. With just a couple more operations (which NumPy has available as built-in functions), you can compute the total amount of kinetic energy passing through your wind turbine in a day. You get to deal with a single variable speeds instead of individually process every value within the list!

Reductions: turning many numbers back into one

An array of 8 powers is progress, but nobody wants to read 8 numbers, let alone 24, and definitely not the 60,000 we’ll meet in week 7. What we want are the handful of numbers that answer the question. Those come from reductions — operations that take a whole array and return one value. Let’s grab the code from above and add a little bit more:

Appending sum, max, min, mean to the end of a NumPy array does what you’d expect them to: sum the values (to a single number), report the maximum value, report the minimum value, and report the mean (average) value. argmax is some new vocabulary: it returns the index where the biggest value occurs. So power.max() tells you what the best hour produced and power.argmax() tells you which hour it was.

ImportantA tricky trace that you’ll get used to

Hopefully I’m not throwing too much at you but: we saw above that speeds[0] gives us the zeroth number within the array of speeds; speeds[4] gives us the “fourth” number in the array. power.argmax() will give us the index where the maximum value of power occurs, and so speeds[power.argmax()] will tell us the speed at which the maximum value of power occurs! It may seem like a tangled mess right now, but with a bit more experience the logic will become intuitive.

Notice we no longer have to inspect the outputs to figure out which is the biggest number, there is a function that does it for us!

A good habit: check the extremes

A problem with tools like .sum: you aren’t checking on every value, so what if there is a bad one?

Weather data conventionally marks missing values with an absurd placeholder like -999, e.g. if the sensor is iced-over or the electronics have a hiccup. Computers do exactly what you tell them to do:

The sum comes back as 2.8e+13 — a number with no error message or warning. It has no minus sign, it didn’t crash, and a tired engineer copies it into a report. It is 28 trillion kilowatt-hours: about 28,000 TWh, which is very nearly a full year of the entire world’s electricity production. I don’t think one turbine did this in six hours!

Important

Look at the extremes before you trust the sum. max() and min() are one line each and they’ll be a sanity check when your data sets are too large to look through in detail.

  • Is the maximum physically possible? Add the power.max() to the code above: huge.
  • Is the minimum physically possible? A negative power means the turbine is consuming electricity from the wind.
  • Then argmax or argmin tells you exactly which reading to go look at.

Seeing it: a first plot

The second most important package in MCEN 1030 is Matplotlib… I think so-named because it stole a lot of plotting conventions from MATLAB. We’ll dive-in to plotting more seriously in a couple weeks, but let’s go ahead and introduce the basic functionality now — it will help us to verify that our data is reasonable.

Some of you went ahead and plotted \(C_p(v) = 0.45[1 - ((v-11)/8)^2]\) last week (using Desmos or something like that) — that’s great! Let’s look at it within Python, and we’ll need to do another import with another nickname:

There’s a couple new functions in here: - np.arange(0, 20.5, 0.5) created an array of wind speeds starting at 0 and taking steps of 0.5 m/s up to (but not including) 20.5 (so it stops at 20.0). In total: 41 values of wind speed stored in an array called v. - We’ve seen this before, but quick reminder: cp(v) evaluated all 41 wind speeds at once. - plt.plot(v, cp(v)) creates a plot where the x-values are the numbers in v and the y-values are the numbers calculated by cp(v).

Concerningly, the curve goes below zero on the left side at \(v = 3\) m/s, and on the right side at \(v = 19\). That is: below 3 m/s the formula reports a negative efficiency, which would mean the turbine generating negative power in a light breeze. That is not physically meaningful, it’s an example of extrapolating an equation outside its meaningful range. We should be asking what should happen at 2 m/s — something is wrong with the equation!
