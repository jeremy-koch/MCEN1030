Your second language

Week 11 — read before Tuesday

Surprise: you’re learning MATLAB today. Bigger surprise: it will take about forty minutes, because — and this is the actual lesson — you didn’t spend ten weeks learning Python. You spent ten weeks learning computing, in a Python accent. Time to prove it.

Think First

Recall

  1. P4 asks you to predict what a short script does. Does anything in that skill actually depend on the language the script is written in?
  2. Week 2: what does an error message owe you? (Hold onto this — MATLAB’s dialect of complaint differs, but the debt is the same.)

Look Ahead

  1. Why would a company pay real money for MATLAB when Python is free?
  2. If an AI translates your Python to MATLAB, what exactly is your job in that transaction?

Why a second language at all

Because mechanical engineering runs on MATLAB in ways you will personally collide with: Simulink (graphical modeling of dynamic systems — the industry standard for controls), decades of validated toolboxes, and forty years of legacy code in aerospace, automotive, and every controls lab on this campus. You will inherit MATLAB code in your career whether you choose to or not. But the deeper reason is the meta-lesson: languages are choices, not identities, and an engineer who can read a language they never studied has demonstrated that the concepts live above the syntax. That’s the department’s “understand differences between languages and choose appropriately” objective — not as a bullet point, but as a lived Tuesday.

The Rosetta stone

The falling wrench, twice:

# Python
def fall_time(h, g=9.81):
    t = (2 * h / g) ** 0.5
    return t

heights = [1.0, 3.0, 10.0]
for h in heights:
    print(fall_time(h))
% MATLAB
function t = fall_time(h, g)
    t = sqrt(2 * h / g);
end

heights = [1.0, 3.0, 10.0];
for h = heights
    disp(fall_time(h, 9.81))
end

Read the MATLAB cold and sort what you see into three bins. Identical: the thinking — a function with a contract, a loop over values, a call per pass. You can already trace this. Cosmetic: % for comments, disp for print, end closing blocks instead of indentation, semicolons suppressing output. Learnable in an afternoon; not worth an anxiety. Genuinely different: two items only, and here they are.

The two real differences

Indexing starts at 1. heights(1) is the first element in MATLAB; heights[0] is the first in Python. This is the single most productive bug-generator in bilingual engineering code, because an off-by-one doesn’t crash — it quietly hands you the wrong element, which then flows through your analysis wearing a straight face (week 2’s silent-error, reborn). Every translation gets its indices audited. Every one.

Matrices are the native object. MATLAB is MATrix LABoratory: everything is a matrix, * means true matrix multiplication (you want .* for element-by-element — NumPy’s default), and linear algebra is home turf rather than an import. This is why controls and vibrations people love it, and it’s a genuine difference of worldview, not spelling.

AI as translator — and the A4 fine print

LLMs translate Python↔︎MATLAB nearly flawlessly; whole-file translation is arguably their single most reliable coding trick. So the production is, as ever, delegated — and your job in the transaction is the audit: run both versions on the same hand-checkable input (your P1 test case rides again, now bilingual) and confirm the outputs match; then specifically eyeball every index and every * that should be .*, because those are precisely the seams where translation slips silently. Same doctrine as week 1, new costume: the translation ran ≠ the translation is right.

Choosing tools: there are right answers

The framework, in priority order — What does the team/legacy code use? What libraries does the task need? What’s the lifespan? — applied to five scenarios:

Quick look at a colleague’s 30-row CSV → Excel (week 7’s ruling stands). Simulating a suspension with a controls team that lives in Simulink → MATLAB, no contest. Fetching API data, wrangling 60k rows, feeding an ML model → Python, whose ecosystem owns that pipeline. Estimating whether a pump can fill the tank by Friday → paper, thirty seconds, no computer; over-tooling is also a tool-choice error. Inheriting 5,000 lines of working, validated MATLAB → MATLAB; rewriting working validated code for language preference is how engineers set fire to a month. Note what never appeared in the framework: “which language do I like.”

Below is a MATLAB script you have never been taught to read. On paper: (1) commit to exactly what it displays; (2) flag the one line you’re least sure about and say why. Bins and indices are your friends.

vals = [4, 10, 6];
total = 0;
for v = vals
    total = total + v^2;
end
disp(total / vals(1))

Thursday is project launch: the menu, the teams, and your project’s first specification — the beginning of the artifact you’ll defend in finals. The languages unit ends where the real work begins, which is the point: from here on, the language is just whichever tool the job wants.
