Reading code and conditional statements

Week 2, Lesson B — read before Thursday

Tuesday we ran code and thought about the results, today we are going to focus on how read and understand the code without needing to run it. Included is an example of the spec → prompt → annotate → verify process. Then we go through conditional statements, which bring us to the interesting and sometimes-confusing world of branching logic: if something is True, do this, but if False, do something else.

Tracing: running code in your head

To trace a program, be the computer: go top to bottom, one line at a time, keeping a little table of every variable’s current value. (Run the code after your trace to confirm your suspicions.)

Tracing is slow and that’s fine — it’s a verification strategy you’ll only deploy on the sections you aren’t sure about

Annotation

When an AI hands you code, you will annotate it. That’s not the same as reading the comments the AI already left, it means writing, in your own words, what every line or logical block does and why it’s there. Producing that explanation yourself, not just reading someone else’s, is what actually proves you understand the code.

Important

Rule 1: A line you can’t annotate is a line you do not understand.

Rule 2: Annotate the why, not just the what. # convert to liters is better than # multiply by 1000. (The latter is probably a repeat of the code!)

One full lap: the 3D-printer problem

The problem: How much filament will it take to 3D-print this part?

Step 1 — Specification. Inputs — part volume (cm³), infill fraction (0–1), filament diameter (mm). Output — filament length needed, in meters. Assumptions — filament is drawn out as a solid cylinder, no waste from priming or purge lines, infill fraction distributed uniformly. Edge cases — zero diameter will raise a division-by-zero error rather than silently returning a bad result.

The slicer is the software that turns a 3D model into printing instructions. The infill fraction is the fraction of a part’s interior that is plastic — if its value is, say, 0.20, the interior of an apparently solid object is a lattice that is 20% plastic and 80% air.

Step 2 — The prompt. The spec practically is the prompt:

Write a Python script that computes the length of filament needed to 3D-print a part. Inputs: part volume in cubic centimeters, infill fraction (0 to 1), and filament diameter in millimeters. Output the filament length in meters including units. Comment each step, including tracking the units/unit conversions along the way.

Step 3 — Annotate what comes back. Suppose the AI returns:

Some initial good news: the code runs without any error messages, and every line is commented and makes sense. We’ve annotated three lines… these are worth checking: are the conversions and equations correct? They are chances for a silent error that would deliver an incorrect output!

You don’t necessarily need to comment every line, especially if the variable names are intuitive. You also might be able to comment on an entire block at once, or if there are repeated steps just describe the first one, or … . Just make sure your code+comments is understandable!

Step 4 — Verify. Hand estimate: the printed volume is \(45 \times 0.20 = 9\) cm³ = 9,000 mm³. The filament’s cross-section is roughly \(\pi (0.875)^2 \approx 2.4\) mm². So the required length is \(\approx 9{,}000 / 2.4 \approx 3{,}750\) mm \(\approx 3.75\) m. We were careful with units here, good. Edge case: set diameter = 0 and predict what happens before running.

You might ask: why did we write a program, and then calculate it by hand anyway? It’s good to have the confirmation — we might not trust the AI, and we might not trust our algebra, but if they agree we can feel better about both. But more importantly: we will get into functions next week, where we write code that can accept different input values, and maybe we use that function 1000 times on a project. With functions, we’ll check on one or two cases by hand, and if it’s good we can feel OK about using that function for the other 998 cases.

When the AI gets it plausibly wrong

The AI might return something like

volume_filled_mm3 = volume_filled_cm3 * 100    # convert cm^3 to mm^3

(E.g., centimeters to meters is a factor of 100… maybe it sees cm and conversion and assumes we are going that way.) It runs and reports a filament length of 0.37 m — maybe believable, but wrong by a factor of ten.

One more thing: if/elif/else

Code tracing through algebra, checking unit conversions and area equations, etc., is important but kind of boring. Let’s go ahead and introduce conditional statements in this reading: they lead to branching… the code takes different paths depending on whether a condition is True or False.

Conditions

Conditions are expressions that evaluate to either True or False. Very useful in coding, e.g. if we are doing a fluid mechanics calculation, the pressure-drop equation we use depends on whether the flow is laminar or turbulent. Our code might check “is the flow turbulent?” If False, it will proceed with the laminar equation; if True, it will proceed with the turbulent equation.

Here are examples of all six basic conditions:

Condition Meaning
x == 5 “x is equal to 5”
b!=3 “b is not equal to 3”
a>3 “a is greater than 3”
a>=2 “a is greater than or equal to 2”
c<-99 “c is less than negative 99”
c<=8 “c is less than or equal to 8”

The double equals == is the “conditional equals”, the single equals = is the “assignment equals”. 5=3 will get you an error, but 5==3 will be interpreted as False, and the program will keep running no problem.

These conditions evaluate as either True or False:

Conditional statements can also be combined, and in Python it is really nice: we get to use the words and and or. Statements with and or or can still be evaluated as True or False

MATLAB, Java, C, C++, and others use && and || for “and” and “or”… not too bad, but not as readable as and and or!

if statements

These are very readable, so let’s just dive in with a basic example:

This is an if statement. If the condition described after the if is True, Python executes the code inside the block that follows; if it is False, it skips it.

In Python, a block is a collection of lines with the same amount of indent level. Python is a unique language in that it defines its blocks based on the indent — in other languages we enclose blocks in braces {} or maybe we introduce a block with an if and end it explicitly with a line that just says end. Many folks enjoy Python because it is uncluttered.

if/else statements

This is pretty intuitive as well:

This is an if/else statement: it checks the condition after the if and, if it’s true, it executes the code within the if block but not the code within the else block. If the condition after the if is false it skips the code within the if block and executes the code within the else block.

if/elif/else statements

A third structure:

In Python, elif is “else if”.

This is an if/else if/else statement: it checks the condition after the if and, if it is True, it executes the if block then skips the elif and else blocks. If the condition after the if is False, it checks the condition after the elif, and if that is True, it executes the elif block and skips the else block. If both the if and elif conditions are False, it executes the code within the else block.

I feel like explaining that in a paragraph might have been more confusing than just reading the code!

Important

You can add more than one elif. The conditions are always checked from top to bottom, and the first one that evaluates as True is the only part of the structure that is actually executed by Python.

It is not mandatory to have an else statement. If none of the if/elif conditions are True and there is no else, it is effectively the same as just skipping the whole block. Sometimes that is desired!

The hardest trace on this page!

Below is an AI-generated script with three planted flaws: one syntax error (won’t run), one loud error (runs, obviously wrong), and one silent error (runs, plausibly wrong). On paper: annotate every line, name all three flaws, trace the if statement and say whether its warning prints, and state what the correct filament length should be. Don’t run it first, you are here to learn!

import math

diameter     = 1.75    # filament diameter, mm
part_volume  = 45      # part volume, cm^3
infill       = 0.20    # fraction of volume actually printed
spool_volume = 285     # cm^3 of plastic on a standard 1 kg spool

volume_filled = part_volume * infill      # cm^3 of plastic actually extruded
volume_mm3    = volume_filled * 1000      # convert cm^3 to mm^3
area          = math.pi * diameter ** 2   # cross-sectional area of filament, mm^2
length_mm     = area / volume_mm3         # mm of filament needed
length_m      = length_mm / 1000          # convert mm to m

if volume_filled > spool_volume:
    print("warning: volume larger than standard spool size")

print("Filament needed:", length_m "m")

We’re building a collection of error messages. In class on Tuesday we encountered NameError (used a variable name Python has never seen before), SyntaxError (the code is not valid Python — it can’t run), and TypeError (e.g., we tried to do math with data that was interpreted as text: in 5+“15”, the 15 is text). Setting diameter = 0 back in Step 4 gives a ZeroDivisionError (you asked Python to divide by zero). When we had inconsistent indentation in the if block, we got an IndentationError.
